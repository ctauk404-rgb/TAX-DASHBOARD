# PDR — 신용카드 전표 자동분류 대시보드

> 상태: 초안 (v0.2 — 엑셀 없이 위하고 자동 연동으로 변경) · 작성일: 2026-10-06 · 사용자: 세무사 본인 (1인 사용)

---

## 1. 배경 및 목적

### 1.1 현재 문제
- 거래처별 신용카드 매입 내역을 위하고(WEHAGO)에서 확인한 뒤, 건별로 **계정과목**과 **부가세 공제/불공제**를 직접 판단해 전표를 입력하고 있다.
- 같은 가맹점이 매달 반복되는데도 매번 같은 판단을 다시 한다.
- 부가세 신고 기간(1·4·7·10월)에 작업이 몰린다.

### 1.2 목표
- 반복되는 가맹점은 **자동으로 분류**하고, 사람은 **애매한 건만 검토**한다.
- 분류 결과는 **위하고에 다시 올릴 수 있는 형식**으로 내보낸다.

### 1.3 성공 기준 (KPI)
| 지표 | 목표 |
|---|---|
| 자동분류율 (검토 없이 확정되는 비율) | 3개월 내 70% 이상 |
| 자동분류 정확도 (검토 시 수정되지 않은 비율) | 95% 이상 |
| 거래처 1곳당 월 카드전표 처리 시간 | 현재 대비 50% 이상 단축 |

## 2. 범위

### 2.1 MVP에 포함
1. **위하고 자동 수집**: 세무사 본인이 로그인하면 거래처별 카드 사용내역을 자동으로 읽어 옴 (엑셀 다운로드·업로드 없음)
2. **규칙 기반 자동분류**: 가맹점명, 업종, 사업자번호 → 계정과목, 공제/불공제
3. **검토 화면**: 미분류 건과 저신뢰 건만 모아서 보기, 일괄 수정
4. 수정한 내용을 **규칙으로 저장**해서 다음 달에 자동 적용 (학습)
5. **위하고 자동 반영**: 세무사가 [승인]한 건만 위하고 전표(계정과목·공제/불공제)에 자동 입력
6. 거래처별 진행 현황 대시보드

### 2.2 MVP에서 제외 (2차 이후)
- 정해진 시간에 사람 없이 돌아가는 무인 자동 실행 (로그인은 항상 본인이 직접)
- AI(LLM)를 이용한 신규 가맹점 추천 분류
- 직원 계정, 권한 관리 (현재 1인 사용)
- 통장, 현금영수증 등 다른 증빙의 자동분류

## 3. 업무 흐름

```
[대시보드] [위하고 연결] 클릭 → 위하고 로그인 창이 뜸 → 본인이 직접 로그인 (2차 인증 포함)
     │  자동: 거래처 목록 → 거래처별 카드 사용내역 읽기
     ▼
[대시보드] ① 자동분류 → ② 검토·수정 → ③ [승인] → ④ 규칙 학습
     │  자동: 승인된 건만 위하고 전표에 입력
     ▼
[위하고] 반영 결과 확인 → 부가세 신고
```

## 3-1. 위하고 연동 방식

| 방식 | 내용 | 장점 | 단점 | 판단 |
|---|---|---|---|---|
| A. 공식 API | 더존이 제공하는 API로 데이터 조회·전표 입력 | 안정적, 약관 문제 없음 | 공개 API가 확인되지 않음 → 더존에 문의 필요 | **가능하면 최우선** |
| B. 브라우저 자동화 | 내 PC의 브라우저를 프로그램이 조작 (사람이 클릭하는 것과 같은 방식). 로그인은 본인이 직접 함 | API 없이 바로 시작 가능 | 위하고 화면이 바뀌면 수정 필요, 이용약관 확인 필요 | **API가 없으면 채택** |
| C. 엑셀 | 다운로드·업로드 | 가장 단순 | 사용자가 원하지 않음 | 장애 시 비상용으로만 유지 |

### 안전 원칙 (방식 B)
1. **비밀번호·인증서를 저장하지 않는다.** 로그인은 매번 본인이 직접 하고, 프로그램은 로그인 이후 화면만 조작한다.
2. **읽기는 자동, 쓰기는 승인 후.** 전표 입력은 대시보드에서 [승인]한 건만 한다.
3. **입력 전후 비교.** 위하고에 넣기 전 값과 넣은 후 값을 기록해 두고, 다르면 즉시 멈추고 알린다.
4. **천천히 조작.** 사람 속도에 가깝게 동작해서 위하고 서버에 부담을 주지 않는다.
5. **실행 기록.** 언제 어떤 거래처의 몇 건을 읽고 입력했는지 남긴다.

## 4. 자동분류 로직

### 4.1 분류 우선순위
1. **거래처 전용 규칙**: 특정 거래처에서 특정 가맹점 → 계정과목 (예: A사 + "OO주유소" → 차량유지비)
2. **공통 규칙**: 가맹점 사업자번호 또는 가맹점명 키워드 → 계정과목
3. **업종 규칙**: 카드사 업종코드나 업종명 → 기본 계정과목
4. 위 규칙에 걸리지 않으면 **미분류**로 남겨 검토 대상에 넣는다.

### 4.2 부가세 공제/불공제 판단 규칙 (초안)
| 케이스 | 처리 | 근거 |
|---|---|---|
| 접대비(기업업무추진비) 성격 | 불공제 | 부가세법 제39조 |
| 비영업용 소형승용차 구입·유지 (주유, 수리 등) | 불공제 | 부가세법 제39조 |
| 면세사업자 가맹점 | 공제 대상 아님 | 세금계산서 등 수취 불가 |
| 간이과세자 가맹점 | 영수증 발급 대상이면 불공제 | 부가세법 제46조 (발급 의무 여부 확인) |
| 목욕, 이발, 여객운송(항공·고속버스·택시 등) 업종 | 불공제 | 부가세법 시행령 제88조 |
| 사업과 관련 없는 지출 | 불공제 | 부가세법 제39조 |

> 위 표는 시스템에 넣을 **기본값 초안**이다. 최종 판단 기준은 세무사 본인이 확정한다.

### 4.3 신뢰도 표시
- **확정 (초록)**: 거래처 전용 규칙과 일치, 과거에 수정 이력 없음
- **검토 권장 (노랑)**: 공통 규칙이나 업종 규칙으로 분류됨, 또는 금액이 평소와 크게 다름
- **미분류 (빨강)**: 일치하는 규칙 없음

## 6. 화면 구성

1. **홈 대시보드**
   - 이번 달 거래처별 진행 상태 (업로드 전 / 검토 중 / 완료)
   - 전체 자동분류율, 미분류 건수
   - 부가세 신고 기한 D-day
2. **연결 화면**: [위하고 연결] 버튼, 연결 상태, 거래처별 자동 수집 진행률
3. **검토 화면**
   - 필터: 미분류 / 검토 권장 / 전체
   - 같은 가맹점을 묶어서 한 번에 분류하기
   - 수정할 때 "이 규칙을 기억하기 (이 거래처만 / 전체)" 선택
4. **규칙 관리 화면**: 규칙 목록, 검색, 수정, 삭제, 적용 통계
5. **반영 화면**: 승인 건 목록, [위하고에 반영] 버튼, 반영 결과와 실패 건 표시

## 7. 기술 스택 (안)

| 항목 | 선택 | 이유 |
|---|---|---|
| 형태 | 내 PC에서 실행하는 웹앱 | 1인 사용, 고객 데이터를 외부 서버에 올리지 않음 |
| 프론트엔드 | React (Vite) | 표와 대시보드 구성이 쉬움 |
| 백엔드/분류 | Python (FastAPI) | 규칙 엔진 구현이 쉬움 |
| 위하고 연동 | 공식 API, 없으면 Playwright 브라우저 자동화 | 로그인 창을 사람에게 보여 주고 이후만 자동 조작 가능 |
| DB | SQLite (로컬 파일) | 설치가 필요 없고 백업이 쉬움 |

## 8. 보안 및 개인정보
- 모든 데이터는 **로컬 PC에만 저장**한다. 클라우드 업로드는 하지 않는다.
- 카드번호는 뒷자리 4자리만 저장한다.
- 위하고 아이디, 비밀번호, 인증서는 저장하지 않는다. 로그인 세션은 프로그램 종료 시 삭제한다.
- DB 파일 백업과 암호화 방식은 2차에서 검토한다.
- 2차에 AI 분류를 도입하면 가맹점명과 업종만 전송하고, 고객 식별정보는 보내지 않는다.

| 5주 | 실제 거래처 1~2곳으로 시범 운영 |

## 10. 결정이 필요한 사항 (Open Questions)
- [ ] 더존에 위하고 API(데이터 조회·전표 입력) 제공 여부 문의
- [ ] 위하고 이용약관에서 브라우저 자동화가 허용되는지 확인
- [ ] 위하고 로그인 방식 (아이디/비밀번호, 인증서, 2차 인증 여부)
- [ ] 카드 사용내역 화면과 전표 분류 입력 화면의 메뉴 경로와 항목
- [ ] 위하고에 이미 있는 카드 자동분개 기능의 범위 (중복 개발 방지)
- [ ] 사용하는 계정과목 코드 체계 (위하고 기본값 그대로 쓰는지, 사무실에서 따로 정한 게 있는지)
